# 開発方針

卒論「視線追跡による絵画鑑賞支援システムの開発と評価」の実装における、技術選定と設計方針をまとめる。

## 研究上の要件（中間発表資料より）

- 視線を鑑賞行動の分析対象としてではなく、作品提示そのものを制御する入力として使う。
- 作品全体を一度に見せず、視線が向いた領域のみを段階的に表示する。一度表示した領域は保持する。
- 専用アイトラッカーではなく、一般的なWebカメラ + Webブラウザ技術で完結させる。
- 評価実験のため、視線移動経路・表示完了までの時間を記録できること。

## 技術スタック

- **React + Vite**。当初は素のHTML/CSS/JavaScriptで組んでいたが、今後アンケート画面や結果ダッシュボードなど画面数が増える見込みのため、途中でReactに移行した。
- 視線推定・マスク描画・ロギングは、Reactに依存しないプレーンなJSクラスとして `src/lib/` に実装し、`src/hooks/useGazeMask.js` から利用する。理由: canvas操作やWebカメラ処理は本質的に命令的で、Reactの再描画サイクルの恩恵を受けにくいため、UI層とロジック層を分離した。
- 視線推定ライブラリ（WebGazer.js等）は未統合。`src/lib/gazeTracker.js` はライブラリ未導入時にマウス座標で代用する設計にしてあり、統合時も呼び出し側のインタフェースは変えずに済む。
